=================================== OVERVIEW ====================================

* We are building ArtAround, a university web project consisting of two interacting applications: a Navigator (Mobile/Visitor) and an Editor (DesktopCurator). We are using a Hybrid Monolith architecture hosted on a single Node.js container (Port 8000) backed by a MongoDB container. Official requirementscan be found in `./requirements.md`
* The implementation target is the Tier 3 (Extension 2, Vote 18-33 - LLM integration)
* On the prod environment (`main` branch), The apps will be hosted on two containers in the computer science department servers (already created):
    - one for node (node-22), which is not directly accessible (only runnable with an entry js script in this repo). The entry script must bind to port 8000;
    - one for mongodb (latest), accesible only 'internally' by the containers hosted exposed in the same domain (such as the node container), or via the custom tool through mongosh (for cli control).
  So there's no need to create Dockerfiles
* On the dev environment (`fede`, at least initally) we're mirroring the two containers environment via the `docker-compose.yml` in the root directory ofthe project
* The initial repository content doesn't matter: *it can be completely refactored*
* Inital tech stack we're considering (eventually the stack can be changed: keep in mind we like simple things!):
  - Backend: Express + zod + openai (for AI integration) + multer for uploads
  - Frontend (Navigator): React + Vite + Zustand + Tailwind + react-leaflet (OpenSreetMap for gelocalization) + custom "Teleport" component overlay thatinjects mock coordinates into the app context for testing.
  - Frontend (Marketplace & Editor): Vanilla JS + Alpine.js + CSS + Tailwind (?).
* Following there are initial ideas for how the apps could be implemented, which are not strict requirements but can be discussed



============================== MARKETPLACE (idea) ==============================

Endpoints:

  * `/editor`: Start page with only the logo in the center, below the login button, an 'about' button which bring you below to a hidden (under viewport) section briefly describing what ArtAround is, and a link to the Navigator endpoint

  * `/editor/museums`: List of selectable museums with two views: 'All Museums' and 'Saved Museums'. Selecting a museum bring you to the `editor/museums/<id-musuem>` endpoint. If you are already logged in, the `/editor` endopint would redirect here.

  * `/museums/<museum-id>`: two views, 'My Visits' and 'Add Items':
        - 'Add Items' show the list of `RawContent` associated with the musuem and the option to (a) create a new item and publish it or (b) select one from the marketplace. Selecting one means adding it to a sort of personal database of items usable in 'My Visits'. In creating an item you likely would have to select a 'tone' from a set of predefined tones,  insert multiple items descriptions with different 'legths' (something like a short brief description, a medium description which add details to the previous one, and a longer one which add details to the medium description; also the length is defined in seconds e.g 3s, 15s, 45s), and an brief description of the tipology of the visits which will be showed when selecting the visit in the Navigator app; then you can choose if publishing it for free or assigning it a price (no need for a real payment feature, just a mockup of it).
        - 'My Visits' is used to create or edit visits. Here you can add to your `Visit` all the `RawContent` you want in the order you want, and for each `RawContent` I likely imagine you would have to select *at least* one associated `Item` (multiple `Item` contents would be used so the user can asks for information in different tones (or maybe another property?) from one of the one you selected). In this section you would also likely have a menu where you can select from of of your `Visit` to edit, or create a new one. In your visit, between two `Item` you could add logistic infos, which are 
    There should be a 'Change Museum' link which brings you back to the museum selection menu.



=============================== NAVIGATOR (idea) ===============================

Endopints:

    * `/`: start page where you can login, create account or go to marketplace.

    * `/museums`: Here you select the museum for which you will select a specic visit

    * `/museums/<museum-id>`: Here you'll see the list of published visits with the brief description and a 'Start Visit' button for each.

    * `/museums/<museum-id>/<visit-id>`: Here you're doing the visit. Here you'll have a picture of the `Item`, a 'Describe!' button (it will start from the shortest description up to the longest each time you press it; the short description will be shown immediatly when you see the item for the first time, without needing to press the button), an 'Ask' button (or something like that) to ask info related to the `Item` (e.g. author, artistic movement, or to describe it with another tone, etc.) or the `Museum` (bathroom location, exit location, etc.), a 'Next' and `Previous` buttons to go to the next and previous `Item`, a 'Map' button which show the museum map.

================================= MONGODB (idea) =================================

Overview:
  * Each `Museum` contains `RawContent`, which represent an entity such as an artist, and artwork, a movement.
  * `Items` represent a personalized presentation of a `RawContent` which will be used for the visits; there can (should!) be multiple `Items` for each `RawContent`.
  * `Visits` represents a sequence of `Items` which the user can interact with in ArtAround Navigator.
  * `Users` represents the user which will login to the app; there should not be a need for multiple roles.
  * `Session` would be used for the synced group visits.
